報告使用實參類型實作 `Iterable`，且接收者是具有相同元素類型的 Kotlin `Collection` 或 `Sequence` 的 `plus`/`minus`。

如果實參類型實作了 `Iterable`，則會將其視為元素集合，而不是單個元素。 這可能會意外地新增或移除多個元素，而不是針對物件本身進行動作。

一個常見的例子是 `java.nio.file.Path`，它實作了 `Iterable<Path>`（遍歷其名稱元素）。 因此，使用 `+` 或 `-` 將 `Path` 新增到 `Collection<Path>` 可能會作用於其組成部分，而不是整個 `Path` 實例。

該檢查包括運算符語法（`a + b`、`a - b`）和顯式呼叫（`a.plus(b)`、`a.minus(b)`）兩種形式。

範例：


// 運算符形式
val paths = listOf(path) + somePath
val paths2 = setOf(path) - somePath

// 一般呼叫形式
val paths = listOf(path).plus(somePath)
val paths2 = setOf(path).minus(somePath)

// 序列
val seq = sequenceOf(path) + somePath

// 路徑 + 路徑（兩側都可迭代）
val combined = path1 + path2  // 返回段列表，而不是組合路徑

快速修復：

  • 轉換為 plusElement/minusElement（將語意更改為最初的意圖）： 
    
val paths = listOf(path).plusElement(somePath)
val paths2 = setOf(path).minusElement(somePath)
val paths3 = sequenceOf(path).plusElement(somePath)
  • 將 Path 實參轉換為集合，以澄清意圖而不改變語意：
    • 對於 plus：使用 toList() 包裝實參以保持順序。
    • 對於 minus：使用 toSet() 包裝實參以提高移除效率。
    
val paths = listOf(path).plus(somePath.toList())
val paths2 = setOf(path).minus(somePath.toSet())
