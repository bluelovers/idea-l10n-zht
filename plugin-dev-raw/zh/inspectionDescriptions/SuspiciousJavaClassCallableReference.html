報告用作可呼叫參照的 kotlin.jvm.javaClass 擴展的可疑情況。

使用 ::javaClass 語法並不會像有人可能預期的那樣生成 Class<T> 實例。
相反，它會建立 KProperty0<Class<T>> 類型的屬性參照，在任何時候，這都是錯誤的，而且會導致意想不到的行為和難以檢測的錯誤。

提供一種修正，以改用直接 .javaClass 呼叫或 ::class.java 語法。

範例 1：表達式接收器

當 ::javaClass 用於表達式時，該快速修復會將其取代為一般 .javaClass 呼叫：


  fun test(a: String) {
      val classRef = a::javaClass  // KProperty0<Class<String>>
      println(classRef)            // 列印“property javaClass”，而非“class java.lang.String”
  }

在套用快速修復後：


  fun test(a: String) {
      val classRef = a.javaClass  // Class<String>
      println(classRef)           // 列印“java.lang.String”
  }

範例 2：類型接收器

對類型使用 ::javaClass 時，該快速修復會將其取代為 ::class.java：


  fun test() {
      val classRef = String::javaClass  // KProperty1<String, Class<String>>
      println(classRef)                 // 列印“property javaClass”，而非“class java.lang.String”
  }

在套用快速修復後：


  fun test() {
      val classRef = String::class.java  // Class<Any>
      println(classRef)                  // 列印“class java.lang.String”
  }
