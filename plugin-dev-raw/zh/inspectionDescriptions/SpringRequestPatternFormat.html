報告 Spring Security 匹配器方法中與自 Spring Security 7.0 起預設使用的 PathPatternParser 不相容的請求模式。

Spring Security 7.0 從使用 Ant 樣式路徑符合 (AntPathMatcher) 切換為 PathPatternParser，對萬用字元段實施更嚴格的規則。

會標記以下模式：

  • 萬用字元段（** 或 {*variable}）放在模式中間，而不是開頭或結尾處。
  • 同一模式中有多個萬用字元段（** 或 {*variable}）。

不正確模式範例：


  http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/**/admin").permitAll()   // '**' 在中間
    .requestMatchers("/{*a}/{*b}").permitAll()      // 多個 {*...} 段
  );

正確模式範例：


  http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/api/admin/**").permitAll()   // '**' 在結尾
    .requestMatchers("/{*path}").permitAll()        // 單個 {*...} 段
    .requestMatchers("/api/*/details").permitAll()  // 單個 '*' 可放在任何位置
  );

該檢查僅在 Spring Security 7.0 或更高版本存在且 spring.mvc.pathmatch.matching-strategy 未設定為 ant_path_matcher 時才會啟用。
